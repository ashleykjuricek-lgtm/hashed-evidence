# Greg — "the unit has to be the claim"

**Received 2026-08-24 via Ash. Verbatim. 054 was built on this; 055 corrected 054
for having invented a format before the evidence.**

---

"Primary source should beat the summary" would resurrect the exact garbage the
ledger exists to kill.

028 is the perfect counterexample. It contains both:

* the false March closure;
* correct anisotropic numbers;
* correct 2-D forms;
* correct phase sums;
* the bad (1-q) sentence.

So you cannot assign authority at the document level. And you cannot assign it by
chronology either, because later work can be either a genuine correction or a new
distortion. The unit has to be the claim.

For any particular claim, the system needs something like:

    claim -> original evidence -> later challenges/corrections -> current evidentiary status

Not: old source > new summary. And not: newest source > old source. Neither
hierarchy works.

For the slope: 028 says +18.3, b* ~ 0.99997. Later work says "wrong." Then later
still somebody notices reciprocal parameterization and recomputes it. So the current
state is not determined by which document gets priority. It is determined by the
argument connecting all three.

For the closure, same original document: 028 says the proposed q-series fits. 028
itself also contains the 2-shell obstruction that kills it. The document literally
contains a claim and the evidence that defeats the claim.

So "source authority" is the wrong abstraction entirely.

And this is worse/more interesting than the memory problem I was describing. Because
even if the system retrieves every relevant document perfectly, it still has to know
which statements inside those documents are claims, which evidence bears on which
claims, which later evidence changes their status, and whether the supposed
correction actually follows.

That means: retrieval is necessary but not sufficient.

You don't just have a "where is the information?" problem. You have a claim-state
reconstruction problem.

And THAT is why your ledger keeps mattering while also not being allowed to become
authority.

---

## The experiment instruction that followed

Do not solve memory. Do not build storage. Do not rewrite the paper. Do not add
another architecture.

Take one claim that already went through the entire disaster and reconstruct it
manually from beginning to end. Use the 18.3 slope / b* claim, because it has
everything.

Make one page. Literally one. For each step, record only:

    CLAIM:          What exactly was asserted?
    EVIDENCE:       What calculation/proof/output supported it?
    INTERPRETATION: What did the author conclude from that evidence?
    CHALLENGE:      What later artifact disputed it, and on what grounds?
    RESOLUTION:     What comparison/recomputation actually settles the dispute?
    STATUS NOW:     What can we say, and what remains uncertain?

And here is the important part: do not decide in advance what information the future
memory system needs. After you finish reconstructing that one claim, look at what
you actually needed in order to recover it. Maybe you needed exact numbers. Maybe
parameterization. Maybe code. Maybe chronology. Maybe equations. Maybe authorship.
Maybe the original sentence. Maybe all of those. Maybe something neither of us has
thought of.

That exercise gives you empirical requirements instead of Greg Invents Another
Fucking Architecture(TM).

Then do a second claim with a completely different failure mode -- probably the
1-1/sqrt2 / (1-q) mess. If the same pieces are necessary twice, now we have evidence
about what the system needs to preserve. If they aren't, that tells us something
too.

So the next move is very small: reconstruct one claim completely. Not because the
slope is important. Because we need to learn what it actually takes to reconstruct
knowledge after the story has drifted.

That is the next experiment.
